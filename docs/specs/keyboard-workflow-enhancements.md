# Spec: Keyboard Workflow Enhancements

> 历史设计，以下伪代码与原快捷键用于保留决策背景。当前实现以 [操作说明](../current-behavior.md) 为准：I 循环标签；O/U 删除/恢复框；Shift+O/Shift+U 删除/恢复图片。标签恢复记录在保存时清空，图片恢复记录在换目录时清空，图片与标注移动不具备事务原子性。

## Problem Statement

当前 labelImg 在数据清理和批量标注场景下效率低下，主要问题包括：

1. **标签审查需要频繁使用鼠标**：用户必须用鼠标点击 label_list 来选中标签，然后按 Delete 删除。一张图片有多个标签时，需要重复多次鼠标点击操作。

2. **缩放比例无法保持**：切换图片时，手动设置的缩放比例会被重置为自适应模式（FIT_WINDOW），导致用户在标注一批尺寸相似的图片时，需要反复调整缩放。

3. **图片删除无法撤销**：删除图片是永久操作，误删后无法恢复，用户在快速清理低质量数据时心理负担重。

## Solution

实现三个键盘优先的增强功能，支持纯键盘工作流：

1. **键盘循环聚焦标签**：加载图片后自动选中第一个标签，按 'h' 键循环遍历所有标签，配合 Delete 键快速删除，无需鼠标介入。

2. **锁定缩放比例**：工具栏 Toggle 按钮锁定当前缩放比例，切换图片时保持固定缩放，适合批量标注同类图片。

3. **临时回收站删除**：按 'o' 删除图片到系统临时目录，按 'u' 恢复最近删除的图片，支持无确认对话框的快速删除，24 小时后自动清理。

## User Stories

1. 作为数据标注员，我希望加载图片后第一个标签自动被选中，这样我可以立即开始审查标签，无需先用鼠标点击
2. 作为数据标注员，我希望按一个键就能循环到下一个标签，这样我可以纯键盘审查所有标签
3. 作为数据标注员，我希望循环到最后一个标签后能回到第一个，这样我可以连续遍历而不用担心边界
4. 作为数据标注员，我希望删除标签后自动选中下一个标签，这样我可以连续删除多个错误标签
5. 作为数据标注员，我希望删除最后一个标签后焦点清空，这样画布上不会有误导性的高亮
6. 作为数据标注员，我希望无标签时按循环键不会报错，这样我不需要在操作前检查标签数量
7. 作为数据标注员，我希望用纯键盘完成"切换图片-审查标签-删除标签"的完整流程，这样我的手不需要在键盘和鼠标之间切换
8. 作为数据标注员，我希望锁定当前的缩放比例，这样我在标注一批相同尺寸的图片时不需要每张图都重新调整缩放
9. 作为数据标注员，我希望锁定缩放后仍可以手动调整缩放，这样我遇到特殊图片时可以临时放大查看细节
10. 作为数据标注员，我希望手动调整缩放后锁定值自动更新，这样下一张图片会应用新的缩放比例
11. 作为数据标注员，我希望点击 FIT_WINDOW 按钮时自动解除缩放锁定，这样我可以快速切回自适应模式
12. 作为数据标注员，我希望按 Ctrl+F 快捷键也能解除缩放锁定，这样键盘和鼠标操作行为一致
13. 作为数据标注员，我希望锁定按钮有明显的视觉反馈，这样我可以一眼看出当前是否处于锁定状态
14. 作为数据标注员，我希望锁定状态不会持久化，这样下次打开应用时是默认的自适应模式
15. 作为数据标注员，我希望快速删除低质量图片，这样我可以高效清理数据集
16. 作为数据标注员，我希望删除图片时不弹出确认对话框，这样我可以快速连续删除多张图片
17. 作为数据标注员，我希望删除的图片可以恢复，这样误删后我不会丢失数据
18. 作为数据标注员，我希望按一个键就能恢复最近删除的图片，这样我可以快速撤销误操作
19. 作为数据标注员，我希望删除图片后自动加载下一张，这样我不需要手动切换图片
20. 作为数据标注员，我希望删除最后一张图片后看到"无图片"提示，这样我知道目录已清空
21. 作为数据标注员，我希望恢复的图片插入到当前位置，这样我可以立即查看恢复的内容
22. 作为数据标注员，我希望删除图片时标签文件也一起删除，这样我不会留下孤立的标签文件
23. 作为数据标注员，我希望恢复图片时标签文件也一起恢复，这样标注数据保持完整
24. 作为数据标注员，我希望删除的文件进入临时回收站而不是永久删除，这样我有短期恢复窗口
25. 作为数据标注员，我希望临时回收站自动清理，这样我不需要手动清理磁盘空间
26. 作为数据标注员，我希望多次删除同一文件时新删除覆盖旧删除，这样我不需要关心回收站的文件管理
27. 作为数据标注员，我希望切换目录后仍能恢复之前目录的删除，这样误删后切换目录不会丢失恢复能力
28. 作为数据标注员，我希望删除标签后可以按 'z' 撤销，这样我可以快速恢复误删的标签
29. 作为数据标注员，我希望标签撤销只对当前图片有效，这样我不会意外恢复其他图片的标签
30. 作为数据标注员，我希望切换图片时标签撤销栈清空，这样每张图片的撤销是独立的
31. 作为数据标注员，我希望删除当前图片时标签撤销栈清空，这样删除的图片不会保留无意义的撤销记录
32. 作为数据标注员，我希望标签撤销和图片撤销是两个独立的系统，这样我可以分别撤销标签和图片操作

## Implementation Decisions

### Module Modifications

**MainWindow (labelImg.py)**:
- 核心应用控制器，包含所有快捷键处理和状态管理
- 新增方法：`cycle_next_label()`, `toggle_lock_zoom()`, `delete_current_image()`, `restore_last_deleted_image()`, `restore_last_deleted_label()`, `cleanup_old_trash_dirs()`
- 修改方法：`load_file()` 添加自动聚焦和锁定缩放逻辑，`set_fit_window()`/`set_fit_width()` 添加自动解锁逻辑，`set_zoom()`/`add_zoom()` 添加锁定值更新逻辑，`delete_selected_shape()` 添加撤销栈记录
- 新增状态字段：`label_deletion_stack`, `image_deletion_stack`, `trash_dir`, `lock_zoom`, `locked_zoom_value`, `lock_zoom_action`

**Canvas (libs/canvas.py)**:
- 绘图画布，已有 shape 选中和高亮逻辑
- 无需修改（canvas 点击标签时已经自动同步 label_list.currentRow()）

**状态管理**:
```python
# 标签撤销栈（当前图片级别）
self.label_deletion_stack = []  # [(shape, item_text, item_flags), ...]

# 图片撤销栈（跨目录级别）
self.image_deletion_stack = []  # [(trash_img_path, trash_label_path, original_dir), ...]
self.trash_dir = None            # %TEMP%/labelImg_trash_{timestamp}/

# 缩放锁定
self.lock_zoom = False           # 是否锁定
self.locked_zoom_value = 100     # 锁定的百分比值
self.lock_zoom_action = None     # 工具栏按钮引用
```

### Keyboard Shortcuts

**新增快捷键**:
- `h`: 循环选中下一个标签（ADR 001）
- `o`: 删除当前图片到临时回收站（ADR 003）
- `u`: 恢复最近删除的图片（ADR 003）
- `z`: 恢复最近删除的标签（ADR 003）

**现有快捷键修改**:
- `Ctrl+F`: Fit to window（已存在，新增触发解锁缩放的副作用）
- `Ctrl+Shift+F`: Fit to width（已存在，新增触发解锁缩放的副作用）
- `Delete`/`Backspace`: 删除标签（已存在，新增记录到撤销栈的逻辑）

### UI Modifications

**工具栏新增按钮**:
- "锁定缩放" Toggle 按钮（QAction with checkable=True）
- 位置：紧邻 FIT_WINDOW 和 FIT_WIDTH 按钮
- 图标：解锁状态 🔓，锁定状态 🔒
- 无键盘快捷键（仅工具栏按钮操作）

**文件列表右键菜单新增**:
- "删除图片" 菜单项（快捷键 'o'，图标：垃圾桶）
- "恢复图片" 菜单项（快捷键 'u'，图标：撤销箭头）

### Behavioral Details

**键盘循环聚焦（ADR 001）**:
- 加载图片完成后，如果 `canvas.shapes` 非空，自动调用 `label_list.setCurrentRow(0)`
- 按 'h' 时计算 `next_index = (current_index + 1) % len(canvas.shapes)`
- 无标签时按 'h' 静默忽略
- 删除标签后 Qt 自动将焦点移到下一个可用 item（或清空焦点如果列表空了）

**锁定缩放（ADR 002）**:
- 点击锁定按钮时记录 `locked_zoom_value = zoom_widget.value()`
- 加载图片时，如果 `lock_zoom == True`，跳过 `adjust_scale()`，直接调用 `set_zoom(locked_zoom_value)`
- 手动缩放时（滚轮、Ctrl++/-、zoom_widget 输入），如果 `lock_zoom == True`，更新 `locked_zoom_value`
- 点击 FIT_WINDOW/FIT_WIDTH 按钮或按 Ctrl+F/Ctrl+Shift+F 时，设置 `lock_zoom = False` 并更新按钮状态

**临时回收站删除（ADR 003）**:
- 应用启动时创建 `%TEMP%/labelImg_trash_{timestamp}/`，清理超过 24 小时的旧 trash 目录
- 按 'o' 删除时，移动图片和标签文件到 trash_dir，记录到 `image_deletion_stack`，清空 `label_deletion_stack`
- 同名文件冲突时覆盖旧文件（`shutil.move` 默认覆盖）
- 删除后加载下一张图片，如果是最后一张则加载上一张，如果列表空了则显示空白界面
- 按 'u' 恢复时，从栈弹出最近删除的记录，移回原目录，插入到当前索引位置，立即加载恢复的图片

**标签撤销（ADR 003）**:
- 删除标签时将 `(shape, item.text(), item.flags())` 压入 `label_deletion_stack`
- 按 'z' 恢复时弹出栈顶，恢复 shape 到 canvas 和 label_list，自动选中恢复的标签
- 切换图片时调用 `label_deletion_stack.clear()`
- 删除当前图片时调用 `label_deletion_stack.clear()`
- 保存文件时调用 `label_deletion_stack.clear()`

### Integration Points

**与现有自动保存的交互**:
- 切换图片时，如果 `auto_saving.isChecked()` 且 `dirty=True`，会触发 `save_file()`
- `save_file()` 末尾调用 `label_deletion_stack.clear()`，确保已保存的删除操作不可撤销

**与现有缩放系统的交互**:
- 现有缩放入口：滚轮（`Canvas.wheelEvent()`）、快捷键（Ctrl++/-/=）、zoom_widget 输入
- 所有缩放操作最终调用 `set_zoom(value)` 或 `add_zoom(increment)`
- 在这些方法中检查 `lock_zoom` 标志，更新 `locked_zoom_value`

**与现有文件列表的交互**:
- 删除图片后从 `m_img_list` 移除，同步更新 `file_list_widget`
- 恢复图片后插入到 `m_img_list`，同步更新 `file_list_widget`
- 文件列表右键菜单已有"删除"项（永久删除），新增"移到回收站"和"恢复"项

### Edge Cases

**键盘循环**:
- 无标签时按 'h' → 静默忽略
- 删除最后一个标签后按 'h' → 静默忽略（Qt 已将 currentRow 设为 -1）
- Canvas 点击标签 → 自动同步 label_list.currentRow()，按 'h' 从当前位置继续

**锁定缩放**:
- 锁定状态下图片尺寸差异大 → 允许，用户可以滚动查看或手动调整
- 切换到新目录时 → 锁定状态保持（会话级状态）
- 锁定值为极端值（如 10% 或 500%）→ 允许，由用户判断

**图片删除**:
- 删除图片但标签文件不存在 → 只移动图片，`trash_label_path = None`
- 临时目录创建失败 → 显示错误，禁用删除功能
- 删除最后一张图片 → 显示空白界面，可按 'u' 恢复
- 恢复时原目录有同名文件 → 覆盖（用户期望恢复的文件替换当前文件）

**标签撤销**:
- 撤销栈为空时按 'z' → 静默忽略
- 保存后按 'z' → 无法恢复（栈已清空）
- 切换图片后按 'z' → 无法恢复（栈已清空）

## Testing Decisions

### What Makes a Good Test

- **测试外部行为，不测试实现细节**：测试用户可见的状态变化（label_list 选中项、canvas 高亮、文件列表内容），而不是内部方法调用
- **使用真实的 Qt 组件**：测试应该创建真实的 QListWidget、Canvas 实例，而不是 mock
- **测试完整的用户操作序列**：按键 → 状态变化 → 副作用（文件移动、焦点变化）

### Modules to Test

**MainWindow 集成测试**:
- 测试键盘循环：加载图片 → 验证第一个标签选中 → 模拟 'h' 按键 → 验证下一个标签选中 → 循环到末尾 → 验证回到第一个
- 测试锁定缩放：设置缩放 150% → 锁定 → 切换图片 → 验证缩放仍为 150% → 手动调整到 200% → 切换图片 → 验证缩放为 200% → 按 Ctrl+F → 验证解锁
- 测试图片删除：删除当前图片 → 验证文件移动到 trash_dir → 验证下一张加载 → 按 'u' 恢复 → 验证文件移回原目录 → 验证图片插入到当前位置
- 测试标签撤销：删除标签 → 按 'z' 恢复 → 验证标签回到 canvas 和 label_list → 切换图片 → 按 'z' → 验证无效果（栈已清空）

**文件操作测试**:
- 测试临时目录清理：创建多个旧 trash 目录 → 启动应用 → 验证超过 24 小时的目录被删除
- 测试同名文件覆盖：删除图片 A → 恢复 → 再次删除 → 验证 trash 中只有一个 A（新覆盖旧）
- 测试跨目录恢复：目录 A 删除图片 → 切换到目录 B → 按 'u' → 验证图片恢复到目录 A

### Prior Art

现有测试结构（`tests/test_io.py`）：
- 使用 `unittest.TestCase` 框架
- 测试读写操作（`PascalVocWriter`, `PascalVocReader`）
- 验证 XML 文件的生成和解析正确性

新测试应遵循相同模式：
- 创建临时测试目录和测试图片
- 实例化 MainWindow
- 模拟用户操作（`QTest.keyClick` 发送按键事件）
- 断言状态变化（`assertEqual`, `assertTrue`）
- 清理测试文件

## Out of Scope

以下功能不在本次规格范围内：

1. **键盘快捷键自定义**：快捷键映射固定为 'h'、'o'、'u'、'z'，不支持用户配置
2. **撤销计数显示**：状态栏不显示"可恢复 N 个标签"或"可恢复 N 张图片"
3. **清空回收站功能**：不提供手动清空临时回收站的 UI（依赖 24 小时自动清理）
4. **工具栏按钮的启用/禁用状态管理**：撤销相关的工具栏按钮（如果添加）不会根据栈是否为空动态更新状态
5. **反向循环快捷键**：只提供 'h' 向后循环，不提供向前循环的快捷键（如 'l'）
6. **标签恢复的插入位置**：恢复的标签追加到 label_list 末尾，不恢复到原始位置
7. **锁定状态持久化**：锁定状态是会话级的，关闭应用后不保存
8. **跨应用实例的回收站共享**：每个应用实例有独立的 trash 目录（通过时间戳隔离）

## Further Notes

### ADR References

本规格实现了以下三个 ADR：
- ADR 001: 键盘循环聚焦标签 (`docs/adr/001-keyboard-label-cycling.md`)
- ADR 002: 锁定缩放比例 (`docs/adr/002-lock-zoom-ratio.md`)
- ADR 003: 图片删除与恢复（临时回收站模式）(`docs/adr/003-image-delete-recovery.md`)

### Design Principles

**纯键盘工作流优先**：
- 所有核心操作都有键盘快捷键
- 自动聚焦减少用户显式操作
- 循环遍历而不是跳转，避免用户记忆索引

**安全的快速删除**：
- 无确认对话框 + 可撤销 = 快速操作 + 安全保障
- 临时回收站 + 自动清理 = 不污染项目目录 + 无需手动维护

**最小惊讶原则**：
- 锁定缩放时手动调整会更新锁定值（而不是忽略或报错）
- 切换到自适应模式时自动解锁（因为两者语义冲突）
- 删除图片时清空标签撤销栈（因为图片已丢弃）

### Performance Considerations

- 标签撤销栈内存占用：每个 shape 对象约 1KB，100 个标签约 100KB，可接受
- 图片撤销栈内存占用：只存储路径字符串，1000 条记录约 100KB，可接受
- 文件移动操作：同磁盘移动是 O(1) 操作（只修改目录项），跨磁盘移动会复制文件（较慢，但用户可感知）
- 临时目录清理：应用启动时执行，glob 匹配 + 删除旧目录，通常 < 100ms

### Accessibility

- 键盘快捷键使用单字母（'h'、'o'、'u'、'z'），易于记忆
- 'h' 来自 Vim 风格导航（hjkl）
- 'o' 类比 "delete" 的首字母 'd'（但 'd' 已被 "下一张图片" 占用）
- 'u' 类比 "undo"
- 'z' 类比通用的 Ctrl+Z 撤销（但这里是单字母，避免冲突）

### Migration Path

本功能是纯增量的，不破坏现有功能：
- 现有快捷键和鼠标操作保持不变
- 不修改文件格式或配置格式
- 不影响现有的自动保存逻辑
- 用户可以选择继续使用鼠标工作流，或逐步采用键盘工作流
